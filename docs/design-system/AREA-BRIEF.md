# Area brief — shared rules for everyone polishing the Creators prototype

Project: `creators/` (single-file HTML prototype assembled from `creators/src/*`). The product logic and navigation are FINAL. We are replacing only the **visual layer** with a standard design system (shadcn/ui-style: Tailwind slate neutrals, blue primary, Inter). The result must look like a modern, calm SaaS app — clean, spacious, consistent.

## What is frozen (never edit)
- `src/chrome.css`, `src/shell.html`: primary rail, secondary nav, the framed content area. Keep exactly as is.
- `src/legacy.css`: GENERATED by `tools/transform-css.js` from the original. Never hand-edit.
- `src/tokens.css`: generated. `src/ds.css`: core component layer — read it, do not edit (request changes in your report).
- Never edit behaviour/markup logic in `src/app.js` unless your brief says so. Do not git commit/push; the main agent does.

## What you may edit
Only your own file `src/areas/<area>.css` (inside `@layer area{ ... }`; it already exists). Cascade order: `legacy < ds < area < chrome`. Because of layers, anything you write in `area` beats legacy rules regardless of selector specificity — so keep selectors simple (class based) and write only what is needed.
You MAY change layout properties in your file when the layout itself is the problem (cramped, misaligned, overflowing, awkward density). Layout *structure* from the markup stays.

## Design system (use tokens only — no raw hex/rgb in your CSS)
- Neutrals: `var(--slate-50…950)`; primary `var(--primary)` (blue-600) / `--primary-hover` / `--primary-soft`; semantic: `--green-*`, `--amber-*`, `--red-*`, `--blue-*`, `--violet-*`, `--sky-*` (use 50 for tint bg, 200 border, 700 text).
- Semantic names: `--background --foreground --card --muted --muted-foreground --border --input --ring --destructive --success --warning`.
- Radius: `--r-sm 6px` (chips, small controls), `--r-md 8px` (buttons, inputs, menus), `--r-lg 12px` (cards, tables, dialogs), `--r-xl 16px` (frame). Pills only for avatars/status dots.
- Shadows: `--shadow-xs` (cards), `--shadow-sm`, `--shadow-md` (menus/popovers), `--shadow-lg` (dialogs/drawers). No other shadows, no glows, no gradients, no stacked-card tricks.
- Type (Inter): 12 caption/meta · 13 dense table text · 14 body · 16 section title (600) · 20 subtitle · 24 page title (600, tracking -.025em) · 30 big KPI. Weights 400 / 500 / 600 only. Sentence case; no ALL-CAPS labels (tiny `eyebrow` at most). Numbers `font-variant-numeric:tabular-nums`.
- Spacing on a 4px grid: 4 · 8 · 12 · 16 · 24 · 32. Page padding 32 (24 on narrow). Space between sections 24. Card padding 16–24.
- Surfaces: page white; cards white + 1px `--border` + `--r-lg` + `--shadow-xs`. Muted surfaces `--slate-50`. Blue tint backgrounds ONLY for: selected/active states, info notes, the primary-soft hover. No blue-tinted big panels, no tinted table headers (table headers are `--slate-50` with muted text).
- One primary (solid blue) button per view; everything else outline or ghost. Destructive = outline red.
- Controls: height 36 (default) / 32 (small). Focus ring 3px `color-mix(in srgb,var(--ring) 22%,transparent)`.
- Tables: header `--slate-50`, 12px muted 500 text; rows 13px, hairline `--slate-100` separators, hover `--slate-50`; numbers right-aligned tabular; first column the strongest text; no vertical cell borders.
- Charts: use the palette in this order — blue-600, sky-500, violet-500, amber-500, green-500, slate-400. Gridlines `--slate-100`, axis text 12px `--slate-500`.
- Dialogs/drawers: white, `--r-lg`, `--shadow-lg`, header/footer separated by `--border`, scrim slate-950 @ 45%.
- Status/badges: neutral by default; ok=green, warn=amber, bad=red, info=blue (50 bg / 200 border / 700 text).

## Quality bar (zero tolerance)
No clipped or overlapping text, no unintended horizontal page scroll, no misaligned columns, no cramped rows, no inconsistent control heights, no orphan icons, no unstyled/default browser controls, no text under 12px, no low-contrast text (muted text no lighter than `--slate-500` on white). Same thing must look the same on every screen in your area and across areas.
